# Offline verifier for the Hermes / Claude / Codex archive

Experimental, non-normative; PMP Core 0.2.2 is unchanged.

The archived replay has separate Hermes, Claude and Codex receipts. This task
provides one offline command to verify their stored Git results, historical
inputs, handoffs and six fixture tests. It uses Python's standard library and
Git. Verification itself needs no subscription, provider, API key or network.

From the experimental repository root:

```powershell
python -B experiments/hermes-pmp/verify_chain.py
python -B experiments/hermes-pmp/verify_chain.py --json
python -B -m unittest discover -s tests -p test_pmp_replay_chain.py -v
```

An alternate archive root may be supplied with `--evidence-root PATH`. It must
contain the exact fixed 2026-10-06 archives; this command is not an importer for
arbitrary bundles. Exit codes are 0 verified, 1 invalid/unavailable evidence,
and 2 invalid CLI usage.

The code pins the three bundle digests and three report digests before any Git
operation. Disposable clones preserve Git blob bytes, disable hooks and run
only the two trusted fixture-test modules. Original archives are read-only.
Temporary verification directories are removed on completion or failure.
Roots and their ancestors reject symlinks/junctions. The semantic helper rejects
all untracked files, including ignored files, before adding a verified clone to
the test process's import path.

Checks cover Git lineage, stage change boundaries, fourteen historical input
hashes, proposals and host receipts, fixture and manifest outputs, canonical
memories, preserved decisions, handoffs, the final Codex receipt and next action.
Historical reports retain their original flags and timestamps.
The returned `next_action`, like `final_commit`, is from the archived fixture
repository. It is not the protocol repository's current task. Read the outer
checkout's root `PROJECT_MEMORY.md` for its current next action.

Digest pins establish integrity relative to the verifier's source revision.
They are not independent signatures. Local tests and consistent stored runtime
labels do not certify model identity, hidden session freshness, reasoning,
general autonomy, remote CI, publication or billed cost. Updating the pinned
archive set requires a separate review of the new observed evidence.

The authorized implementation handoff is defined in
[CHAIN_TASK.md](../../experiments/hermes-pmp/CHAIN_TASK.md). Claude proposes the
single code file without tools; the host reviews/imports it and runs acceptance.
An independent Codex reviewer then receives repository state and evidence only.
The single Claude invocation reached the five-minute timeout without a retained
complete proposal. Codex completed the code locally; there was no retry. This
does not validate the planned Claude implementation handoff. Existing real
Hermes/Claude/Codex replay evidence remains unchanged and is what the offline
command verifies. Provider-request count, consumption and invoice impact for
the timed-out attempt are unknown. Existing subscription login was used; no
new service, credits or plan was purchased.

Host verification passed all six new acceptance tests and full repository
discovery (82 tests), plus unchanged Core memory/release checks. The final
historical Codex receipt uses a paraphrase; both its bytes and canonical memory
are pinned, and the command returns the canonical action. Test execution uses
a fixed isolated Python bootstrap to load only the two named trusted modules.

The independent reviewer reconstructed the task from a separate repository
snapshot with no inherited conversation. It found two P2 issues in that first
candidate: ignored files could shadow imports in the semantic helper, and
ancestor links were not rejected. The host corrected both and passed seven
acceptance tests and the full suite (83). A harmless ignored-module regression
proves rejection before its marker can be written; focused predicate tests cover
symlink/junction ancestors. A real Windows junction probe was unavailable in the
sandbox, so no real-junction end-to-end claim is made. The CLI subprocess uses
-B to avoid generated bytecode. At that checkpoint there was one review; host
verification of fixes is separate from that original review.

Evidence is in `experiments/hermes-pmp/evidence/chain-verifier-20261006/`:
dispatch/input packet, bounded timeout, initial host checks, reviewed snapshot
manifest, independent receipt and final host checks. Earlier records remain
historical; final-checks.json identifies the corrected source/test digests.
The useful offline command is complete. The proposed Claude implementation
handoff is **PARTIALLY VALIDATED**: dispatch worked, but no complete Claude
implementation was obtained. Comparative savings and invoice impact were not
measured. The earlier fixture chain retains its separate, bounded conclusion.

Two later same-host reproductions (Claude Code and Google Antigravity) reported
the corrected verifier and all seven acceptance tests passing at outer commit
8c96e926b0d28a182759c45c3a0141fa9a934eba. See
[reports and maintainer assessment](../../experiments/hermes-pmp/evidence/reproductions/README.md).
They do not establish external-machine reproduction or certified model/session
identity. The initial review, later runtime reports and maintainer checks are
separate evidence records; the fixed archived chain has not been changed.

Windows sandbox note: if the default temporary folder denies writes, set TEMP
and TMP to an accessible disposable-work directory outside the clone before
running tests. This
does not change the archive source or the validator. Use an absolute path for
`--evidence-root` when an environment resolves relative directories incorrectly.
Use short Windows checkout paths to avoid MSIX/AppData path-length failures.
The brief supplies matching outside-clone Windows and POSIX temp examples;
POSIX reproduction has not yet been observed.
